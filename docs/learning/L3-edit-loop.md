# L3：edit_file 与 Diff

`edit_file` 是 Agent 从“观察代码”进入“改变代码”的边界。

它不接受行号和模糊指令，而是要求模型提供：

```text
path
oldText
newText
```

只有当 `oldText` 在文件中恰好出现一次时才写入。

## 为什么 0 次和多次都拒绝

- 0 次：模型可能读到了旧版本代码，继续修改会产生错误结果。
- 多次：模型没有说明到底要改哪一处，自动猜测可能破坏其他逻辑。

拒绝猜测比“尽量帮模型改”更安全，也更容易调试。

## 为什么先生成 Diff

修改前后都会计算 SHA-256，并生成 unified diff。这样每次修改都有：

- 修改前指纹；
- 修改后指纹；
- 精确的变更文本；
- `file.changed` 事件。

Diff 是模型、用户和 Verification 共同观察修改的标准语言。

## 为什么使用临时文件再 rename

如果直接覆盖原文件，进程在写到一半时崩溃，可能留下半个文件。

当前实现先写同目录临时文件，再 rename 到目标路径。这样写入失败时，原文件仍然保持完整。

## 本阶段的边界

当前只实现字符串精确替换，还没有实现：

- 多文件 patch；
- AST 级别修改；
- 自动格式化；
- 人工审批 UI。

这些能力要等最小闭环和 Verification 稳定后再增加。
